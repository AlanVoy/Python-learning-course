# Реестр заданий курса Python

Назначение: постоянный индекс уже встречавшихся задач, чтобы при повторениях не выдавать дубликаты под новым названием.

## Правила использования реестра
1. Перед созданием задания на повторение сверять цель задачи, алгоритм и ключевые конструкции с этим индексом.
2. Совпадающая цель считается повтором, даже если изменены числа, имена переменных или формулировка.
3. Допускается повтор темы только с явной целью: закрепление, исправление выявленной ошибки или усложнение. Тогда записывать отличие.
4. Не считать отсутствие файла доказательством, что тема не изучалась: сначала уточнять у пользователя.
5. Условия заданий не хранятся отдельно в архиве, поэтому описания ниже восстановлены по коду и являются предварительными там, где исходное условие не приложено.

## Инвентаризация архива
- Найдено 47 файлов `.py`.
- Нет стандартных файлов `lesson_05.py`, `lesson_06.py`, `lesson_09.py`, `lesson_10.py`.
- Есть `lesson_33(1).py` и `lesson_33(2).py`, но нет файла с точным именем `lesson_33.py`: это две реализации одной задачи.
- `lesson_50.py` пуст.
- Синтаксически не разбирается `lesson_12.py`.

## Результаты проверки кода

Проверка синтаксиса выполнена для всех 47 файлов. Далее — обнаруженные проблемы по статическому чтению; это не заменяет полный прогон с тестовыми входными данными.

| Файл | Статус | Наблюдение |
| `lesson_12.py` | Критическая ошибка | Синтаксис не разбирается: `else num > 0:` недопустимо в Python. Из-за этого файл не запускается. |
| `lesson_31.py` | Логическая ошибка | В цикле проверки цифры, после третьего повторного ввода счётчик увеличивается и вызывается `exit()` без повторной проверки введённого значения. Даже если на последней попытке введена допустимая цифра, программа завершится. |
| `lesson_32.py` | Граничный случай | Проверка палиндрома не нормализует отрицательное число. Отрицательные значения обычно будут признаны непалиндромами; нужно явно решить, допустимы ли отрицательные входные данные по условию. |
| `lesson_40.py` | Логическая ошибка | При совпадении второго числа с первым код запрашивает дополнительное число внутри цикла и одновременно изменяет счётчик. Это может привести к чтению лишних значений и нарушению заданного количества вводов. |
| `lesson_44.py` | Логическая ошибка | Если изначально введено количество меньше 2, повторный ввод может исправить его, но обработка последовательности находится в `else` исходного `if`, поэтому после исправления программа всё равно пропускает задачу. |

## Тематические кластеры — для поиска повторов

- Ввод, типы и строки: `lesson_01.py`–`lesson_04.py`.
- Условия и возрастные диапазоны: `lesson_07.py`, `lesson_08.py`.
- Базовые циклы, накопители и sentinel `0`: `lesson_11.py`–`lesson_22.py`.
- Арифметика цифр числа: `lesson_23.py`–`lesson_31.py`.
- Палиндром и переворот числа: `lesson_32.py`, `lesson_33(1).py`, `lesson_33(2).py`.
- Числовые свойства и делители: `lesson_34.py`–`lesson_39.py`.
- Последовательности и серии: `lesson_40.py`–`lesson_49.py`.

## Как обновлять базу
Для каждого нового задания добавлять запись с: уникальным ID, датой, краткой целью, входными данными, ожидаемым результатом, алгоритмическим типом, конструкциями Python, похожими прошлыми задачами и статусом проверки.
Перед выдачей нового задания сравнивать не только названия, но и саму операцию, которую должна выполнить программа.
