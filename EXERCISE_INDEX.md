# Реестр заданий курса Python

Назначение: постоянный индекс уже встречавшихся задач, чтобы при повторениях не выдавать дубликаты под новым названием.

## Правила использования реестра
1. Сравнивать цель и алгоритм, а не только названия, числа и переменные.
2. Считать одинаковую задачу с другими числами смысловым повтором.
3. Разрешать повтор только как явно обозначенное закрепление, исправление или усложнение.
4. Отсутствие файла не считать доказательством, что тема не изучалась.
5. Описания по старым файлам восстановлены по коду и могут требовать уточнения исходного условия.

## Инвентаризация репозитория
- Ветка: `main`.
- В папке `lessons/` — **52 файла `.py`**: `lesson_01.py`–`lesson_51.py` и дополнительная версия задания №29.
- Для задания №29 есть `lesson_29_v1.py` и `lesson_29_v2.py`; отдельного `lesson_29.py` нет.
- Пропусков в основной нумерации, кроме заменённого двумя версиями №29, нет.
- Пустых файлов в актуальной инвентаризации нет.

## Ранее отмеченные вопросы для повторной проверки

**Важно:** замечания ниже относятся к старой проверке и после переименования не были заново подтверждены. Это не список доказанных текущих ошибок.

| Файл | Историческое замечание |
|---|---|
| `lesson_08.py` | Ранее зафиксировано: Синтаксис не разбирается: `else num > 0:` недопустимо в Python. Из-за этого файл не запускается. |
| `lesson_27.py` | Ранее зафиксировано: В цикле проверки цифры, после третьего повторного ввода счётчик увеличивается и вызывается `exit()` без повторной проверки введённого значения. Даже если на последней попытке введена допустимая цифра, программа завершится. |
| `lesson_28.py` | Ранее зафиксировано: Проверка палиндрома не нормализует отрицательное число. Отрицательные значения обычно будут признаны непалиндромами; нужно явно решить, допустимы ли отрицательные входные данные по условию. |
| `lesson_36.py` | Ранее зафиксировано: При совпадении второго числа с первым код запрашивает дополнительное число внутри цикла и одновременно изменяет счётчик. Это может привести к чтению лишних значений и нарушению заданного количества вводов. |
| `lesson_40.py` | Ранее зафиксировано: Если изначально введено количество меньше 2, повторный ввод может исправить его, но обработка последовательности находится в `else` исходного `if`, поэтому после исправления программа всё равно пропускает задачу. |
| `lesson_41.py` | Ранее зафиксировано: Если изначально введено количество меньше 3, повторный ввод может исправить значение, но основной алгоритм находится в `else` исходного `if`; после исправления задача не выполняется. |
| `lesson_42.py` | Ранее зафиксировано: Если изначально введено количество меньше 2, повторный ввод может исправить значение, но основной алгоритм находится в `else` исходного `if`; после исправления задача не выполняется. |
| `lesson_45.py` | Ранее зафиксировано: В ветке обработки невозрастающего перехода счётчик текущей возрастающей серии не всегда сбрасывается в 1. На последовательностях с несколькими разрывами может быть завышена максимальная длина. Нужна проверка на контрпримерах. |
| `lesson_29_v1.py и lesson_29_v2.py` | Ранее зафиксировано: Оба файла решают одну задачу — переворот числа арифметически без строк. Сохраняем как две реализации одной задачи, а не как два разных задания. |
| `lesson_29_v1.py и lesson_29_v2.py` | Обе версии относятся к арифметическому перевороту числа; не считать отдельными алгоритмическими заданиями. |

## Тематические кластеры — для поиска повторов

- Ввод, типы и строки: `lesson_01.py`–`lesson_04.py`.
- Условия и возрастные диапазоны: `lesson_05.py`–`lesson_06.py`.
- Базовые циклы и накопители: `lesson_07.py`–`lesson_18.py`.
- Арифметика цифр числа: `lesson_19.py`–`lesson_27.py`.
- Палиндром и переворот числа: `lesson_28.py`, `lesson_29_v1.py`, `lesson_29_v2.py`.
- Числовые свойства и делители: `lesson_30.py`–`lesson_35.py`.
- Последовательности, серии и прогрессии: `lesson_36.py`–`lesson_46.py`.
- Частоты, уникальные элементы и сортировка без коллекций: `lesson_47.py`–`lesson_51.py`.

## Как обновлять базу
Для каждого нового задания добавлять запись с уникальным ID, целью, входными данными, результатом, алгоритмическим типом, конструкциями Python, похожими задачами и статусом проверки.
Перед выдачей нового задания сравнивать цель и алгоритм, а не только названия.
